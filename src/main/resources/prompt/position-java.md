\## 6. Java 系统设计题



\### 通用系统设计题

\- \*\*短链服务\*\*（日 PV 1 亿）：短链生成算法（hash/自增 ID/雪花）、分库分表、缓存设计、高可用

\- \*\*秒杀系统\*\*（10 万 QPS、100 库存）：限流、Redis 预减库存、超卖防护（乐观锁/Redis Lua）、MQ 削峰

\- \*\*IM 系统\*\*（千万级在线用户）：长连接选型、心跳机制、消息可靠投递、离线消息存储

\- \*\*分布式任务调度平台\*\*：任务分片、失败重试、幂等、调度高可用

\- \*\*电商订单系统\*\*（高并发、分库分表）：订单号生成、库存扣减、订单状态机、对账



\### 考察点

\- 需求拆解（功能性 + 非功能性）

\- 容量估算（QPS、存储、带宽）

\- 模块划分与数据流转

\- 数据库设计（分库分表、索引）

\- 缓存策略（多级缓存、一致性、热 key）

\- 限流降级（令牌桶、熔断、降级方案）

\- 高可用保障（多机房、主备切换、数据备份）

\- 扩展性设计（水平扩展、垂直拆分、服务化）



\## 评分标定示例

问：HashMap 在 Java 8 后的优化是什么？

\*\*VERY\_FAMILIAR\*\*
答：链表长度 ≥8 且容量 ≥64 时转红黑树，因为链表 O(n) 会退化成红黑树 O(log n)。
同时尾部插入避免死循环。
（特征：说清条件、原因、并发改进）

\*\*FAMILIAR\_BUT\_SHALLOW\*\*
答：链表太长时用红黑树代替，提高查询效率。
（特征：知道方向，说不出条件和原因）

\*\*NOT\_FAMILIAR\*\*
答：用了某种树结构优化。/ 答：我不太了解这块。
（特征：答非所问或明确不知）
